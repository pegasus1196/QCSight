# CabinetSight — Project EAGLE EYE

**AI vision for control-cabinet quality control: photo + drawing in, marked-up QC report with proof out.**

> VIT Code Apex 3.0 · Emerson Problem Statement #03 · Team **null set**
> Anjali Tripathi (leader) · Siddharth Tripathi · Pooja Lingwat · Piyush Dadwani

## The problem

A QC inspector checks every part, label, wire and ferrule in a control cabinet by eye against the
drawing, then fills the check sheet by hand. It is slow, unproven and easy to miss things.

## What CabinetSight does

| Step | What happens |
|------|--------------|
| 1. Inspection inputs | Cabinet photo, GA drawing (PDF), wire list and label list (Excel) |
| 2. Inspect | Find parts, read device labels and ferrules |
| 3. Compare | Match the photo against the drawing and lists |
| 4. QC checklist | PASS / FAIL / UNREADABLE per item, with photo evidence (expected vs found) |
| 5. Re-check after fix | New photo re-runs the open items; fixed items are marked **CLOSED**; run history kept |

**Design rule — no false alarms:** a correct item must never be marked FAIL. When the tool is not sure,
it says **UNREADABLE** and asks for a close-up instead of guessing.

### Checks in this run (plug-ins)

| Check (UI name) | Status |
|-----------------|--------|
| Device presence | MUST |
| Device labels | MUST |
| Wire ferrules | MUST |
| Photo alignment | Supporting |
| Wire colour | Stretch |

## Current status (Round 1 prototype)

What is in this repo today:

| Layer | Implementation |
|-------|----------------|
| Frontend | HTML / CSS / JavaScript single-page UI (`index.html`, `src/`) — upload, QC checklist, photo evidence, re-check, run history, CSV/print export |
| Backend | Python, FastAPI + Uvicorn (`backend/`, `run.py`) |
| Computer vision | OpenCV (ORB/SIFT feature matching, homography, HSV colour) |
| OCR | EasyOCR, Tesseract fallback, RapidFuzz matching |
| Detection | Ultralytics YOLO11n training pipeline (`backend/training/`) on the public [LibreYOLO/circuit-elements](https://huggingface.co/datasets/LibreYOLO/circuit-elements) dataset (CC BY 4.0) |
| Test data | Synthetic cabinet sets in `assets/test-inputs/` (generated by `backend/generate_test_images.py`) |

If the backend is not running, the UI falls back to built-in **demo results** (clearly labelled DEMO RESULTS).

## Round 2 build (15–18 Oct) — target stack

| Layer | Technology |
|-------|-----------|
| Frontend | React · TypeScript · Vite · Tailwind · Konva (evidence overlay) · typed API client from OpenAPI |
| Backend | Python 3.11 · FastAPI · Pydantic · PyMuPDF · pandas · plug-in rule engine (YAML) |
| AI | YOLOv8 → ONNX Runtime · PaddleOCR · OpenCV · RapidFuzz · local LLM for report wording only (never verdicts) |
| Database | PostgreSQL (runs, rules, history) · local file store for photos |
| DevSecOps | Docker Compose + Nginx (on-premise, offline) · GitHub Actions: pytest, Playwright, false-alarm gate, Trivy, gitleaks, SBOM |

Full requirements: see the PRD (64 EARS requirements) shared with the team.

### How we will prove it (targets, measured by our evaluation harness)

- **0 false alarms** — a correct item is never marked FAIL
- **Unseen cabinets** — tested on cabinets never used for training, with planted faults
- **< 60 s per inspection** on a laptop CPU

## Run it locally

```bash
git clone https://github.com/pegasus1196/QCSight.git
cd QCSight
python -m venv venv
# Windows: venv\Scripts\activate    Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
python run.py
```

Open `http://localhost:8000`. Tesseract is optional (fallback OCR):
Windows installer — https://github.com/UB-Mannheim/tesseract/wiki · Ubuntu — `sudo apt install tesseract-ocr`.

UI only (no backend): open `index.html` in a browser and choose **Try demo data**.

## Known limitations (honest list)

- Prototype results in the UI are demo data unless the backend is running.
- The YOLO model is not yet trained on real Emerson cabinet photos (public dataset only).
- Current OCR scoring can mark very low-confidence reads as FAIL; Round 2 changes this to UNREADABLE
  to meet the no-false-alarm rule.
- Photo-evidence markers are not yet scaled to the rendered image; fixed in the React build.

## Privacy

All processing runs locally — no cloud calls, no telemetry. Organiser sample data is not committed to this repo.
